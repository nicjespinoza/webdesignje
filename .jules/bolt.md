## 2025-05-19 - O(n²) Distance Check Optimizations
**Learning:** In Three.js and 2D canvas apps, loops computing distance across O(n²) entities (e.g., node connections) frequently use `distanceTo()`, which internally calls `Math.sqrt()`. While hoisting thresholds (`thresholdSq`) and using `distanceToSquared()` is standard, note that inside `NeuralNetwork` for `Scene3D.tsx`, `j > i` iteration avoids duplicate checks and works nicely for symmetric logic. However, for `components/landing/Scene3D.tsx` where opacity blending might rely on duplicate/asymmetric data or `n1.layer` dependencies, changing iteration bounds can break visual rendering. Keep iteration bounds consistent with rendering semantics.
**Action:** When optimizing loop `distanceTo()` calculations, always hoist the squared thresholds and use `distanceToSquared()`. Ensure loop bounds (`j > i`) are only reduced when visually verified that asymmetric/duplicate rendering passes aren't affected.
