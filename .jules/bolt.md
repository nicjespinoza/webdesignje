## 2025-02-20 - Math.sqrt bottlenecks in nested Three.js loops
**Learning:** In Three.js and 2D canvas rendering (like in `Scene3D.tsx` generating node connections), using `Math.sqrt` via `distanceTo()` inside O(n^2) loops causes significant performance drops due to the mathematical overhead on every frame or memoized calculation. Furthermore, optimizing these O(n^2) loops by halving the iterations (`for (let j = i + 1...)`) must be done with extreme care. In this codebase's specific architectural pattern for visual rendering, duplicate pairs (e.g., A->B and B->A) are intentionally drawn to accumulate opacity via WebGL additive blending, and asymmetric layer checks exist where the threshold depends solely on the first node (`n1`). Breaking this symmetry visually regresses the glowing scene effect.
**Action:** Always replace `distanceTo()` with `distanceToSquared()` in hot paths and compare against a squared threshold. When refactoring O(n^2) loops for performance, specifically verify if the rendering logic implicitly relies on duplicate iterations for visual strength (opacity accumulation) or if conditionals are asymmetric before aggressively pruning iterations.
