## 2024-05-27 - distanceTo Squared Optimization
**Learning:** In Three.js applications, distance calculations (`Math.sqrt(...)` or `distanceTo(v)`) in nested loops or high-frequency animation loops (`useFrame`) can be expensive. However, replacing `distanceTo(v) < threshold` with `distanceToSquared(v) < threshold * threshold` is a safe and effective optimization. When optimizing node connections in an O(n^2) loop (e.g., in `Scene3D.tsx`), it's tempting to also halve iterations by starting the inner loop at `j = i + 1`. But, as noted in memory: "When generating node connections in O(n^2) loops (e.g., `Scene3D.tsx`), be aware that halving iterations (`j = i + 1`) can cause critical visual regressions and logic bugs if the rendering logic relies on duplicate line pairs for opacity accumulation, or if threshold/strength calculations are asymmetric". Therefore, keep the iterations but use the squared distance.
**Action:** Replace `distanceTo` with `distanceToSquared` and compare against `threshold * threshold` to avoid the square root overhead, without modifying the loop structure.
