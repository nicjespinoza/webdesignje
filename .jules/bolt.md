## 2026-04-26 - Avoid Square Root in 2D Canvas Animations & Correct O(n^2) Loop Indexing
**Learning:** `Math.sqrt()` is relatively expensive to compute. When analyzing particle collision or connection logic inside nested loops executed every animation frame, calculating the Euclidean distance via square root for all pairs creates a measurable CPU bottleneck. Also, evaluating connections backwards (e.g. `j = i` or `j = 0` when connecting points in an undirected network) doubles the iteration count and overdraws the canvas unnecessarily.
**Action:** Always prefer squared distance comparisons (`distSq < threshold * threshold`) over absolute distances for initial hit-testing and threshold filtering. Only compute `Math.sqrt(distSq)` when the actual distance value is required (e.g., for calculating exact interaction forces or opacity values) and strictly inside the conditional block. Furthermore, when generating undirected node connections in an O(n^2) operation, always initialize the inner loop as `for (let j = i + 1; j < nodes.length; j++)` to halve calculations and prevent duplicate stroke rendering.
