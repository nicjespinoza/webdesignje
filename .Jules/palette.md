## 2024-05-23 - Hardcoded Colors & i18n Translation Context
**Learning:** Adding new UX improvements (like `aria-label` and `focus-visible:ring-`) can be risky when dealing with custom hex colors vs design tokens, and translations. Next.js production builds can break if `t('string')` is undefined or accessed improperly outside the component context. Furthermore, although adding new arbitrary hex colors is generally frowned upon, some components (`components/landing/Navbar.tsx`) heavily use hardcoded hex values (like `#C69320`) for focus states or branding instead of semantic theme variables.
**Action:** Always verify translations using the standard translation namespace and fallback structures provided in `lib/i18n.ts` instead of directly writing strings if `react-i18next` is being used. Be consistent with the existing style implementations in the file, whether that implies custom hex strings or semantic tailwind classes, but prioritize checking existing definitions.
